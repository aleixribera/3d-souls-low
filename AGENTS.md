# Project Guidelines

Current version: **v7.17.0** (v7.17.0 — Steadier Battles) (`VERSION` in `js/config.js`). The game is complete: two Story roads (Ashmere: Tutorial, Levels 1–5, the ending; the Lands Between: eight lands, one per Elden Ring boss, its own ending), plus Levels, the 1v1 Arena (Enemies, Bosses, Elden Ring Bosses), with its lore told by an NPC, inscriptions and scenes. v5.2 added executions; v5.3 added the Elden Ring Bosses mode and its first boss, Margit; v5.4 added the second, Godrick the Grafted; v5.5 added the third, the Crucible Knight; v5.6 added the fourth, Morgott, the Omen King; v5.7 added Radagon of the Golden Order; v6.0 added the Ultra graphics preset, remade models, boss attack effects and a visual overhaul of the levels. v6.1 reduces rendering overhead, model subdivision and loading time while preserving the main Ultra effects. v6.2 doubles the three pre-Aldric story bosses' health, adds borrowed Elden Ring moves, and optimizes Low graphics at native resolution with shared texture maps and improved loading. v7.0 adds the second road, eight new enemies, the realm set pieces and the regrouped menus (see the last section).

**`LORE.md` is the source of truth for the story** (Part II: the Lands Between). Every in-game story text (dialogues, inscriptions, chapter lines, boss names, level descriptions, ending cards) must agree with it. Change the story in LORE.md first, then in the game, and keep LORE.md updated.

## Tech Stack
- **Engine / Core:** Vanilla JavaScript (ES6+), Three.js r160[cite: 1].
- **Structure:** Classic scripts loaded via `<script>` tags sharing a global execution context, loaded strictly in the order listed in `GAME_FILES` inside `combat-arena-3d.html`[cite: 1].
- **Dependencies & Tooling:** Zero build steps, bundlers, or third-party npm runtime dependencies[cite: 1].

## Bot following and walking routes (v7.15.0)
- In normal levels, idle bots follow living, participating humans, never other bots. `BotNavigation.assign` splits living bots evenly; surplus slots go to humans nearest the remaining living enemies (including dormant/lurking ones). One bot therefore follows the front player even if somebody else is nearer the bot. Assign by stable player id, retain valid slots, refresh on the configured clock and immediately on roster/death changes. Combat acquisition still takes priority and ordinary level sight/range rules remain.
- `js/bot-navigation.js` searches actual collision floors with layers, ramps, solids, gates, hazards and opened holes. A* advances in bounded batches and shares lazy geometry samples. A moving target must not continually cancel an unfinished search. Gate/trap/floor changes invalidate connectivity. Required drops use ordinary Player falling and damage; pits and excessive falls are rejected.
- Follow hysteresis walks from the outer gap to the inner gap. Remove distance/floor-based catch-up warps. Only eight seconds of failed physical movement while free/grounded, with an existing route, permits a 1–3 m safe reposition along it. Long healthy detours, combat, airborne/stunned time and closed gates cannot authorize a catch-up teleport. Tuning: `CONFIG.bot.follow`, `assignmentTime`, `navigation`.
- Checks: `tests/bot-follow.cjs` covers fair ratios, single-bot/front priority, stable identities, walking, walls, spiral stairs, rot, floor holes, gates, required drops, stuck recovery, moving targets and all 14 normal maps. Also run bot behavior/duels/integration, multiplayer/lobby checks and the full solo browser suite. See `docs/bot-following-v7.15.0.md`. VERSION / LOAD_STAMP: v7.15.0 / 7.15.0.

## Persistent public lobby (v7.14.0)
- The server ticks every active session even with zero ready/connected humans. Leaving never resets a run or removes its bots. This supersedes the v7.8.2 deliberate-leave reset and 60-second empty-lobby expiry. Normal wins, team wipes and explicit leader controls still own progression/reset. With no living actors, enemies finish attacks/phases and return home while world timers progress.
- Client focus/visibility sends `presence`, saving a final pose first. Background or stale poses do not participate in combat/leader election. Fresh real input may immediately regain available leadership; pings, poses and focus alone never renew the five-minute input clock. Active loading peers and the overall startup barrier have `ArenaNet.config.loadTimeout` (30 seconds), which reconnects cannot extend; away/expired loaders cannot block it. Confirmed deaths keep their wipe clock even when poses become stale.
- A private server-issued token in same-origin localStorage recovers the same player id/name and validated personal resources in the same epoch. Memory is bounded by `rememberedPlayers` and lasts for the server process. Tokens never enter rosters/frames; matching names grant no identity. One token owns one connection; replacing a socket cannot let its later close delete its successor. A new encounter gets its normal spawn/refill, and saved boss defeat cannot be bypassed by rejoining.
- Restore personal state only in the start/reconnect packet, never from ordinary snapshots. Cancel old action animations; preserve actual health/stamina/flasks, exhaustion and Destined Death. A final leave/away pose captures the latest resources. Volume defaults to 5; saved volume 8 migrates to 5 while other preferences remain.
- Checks: `tests/lobby-continuity.cjs`, `tests/reconnect-browser.cjs`, leader, multiplayer/campaign, boss-only, wipe, bot, network and settings regressions plus the full solo browser suite. See `docs/persistent-lobby-v7.14.0.md`. VERSION / LOAD_STAMP: v7.14.0 / 7.14.0.

## Bot risk and solo pace (v7.13.1)
- Profiles' `greed` and `forward`, with `CONFIG.bot.risk`, own short attack gambles and inward rolls. A greedy exchange can spend more stamina, extend a combo into a shorter window and keep swinging through its target's wind-up. Damage ends the gamble. Another opponent or a projectile still takes defensive priority. Choices run on bounded clocks, never per-frame retries or enemy ids.
- Forward rolls may meet the boss's body or finish inside the attack; they use ordinary collisions and i-frames and can be punished. Only some anticipate the attack early. Keep wall/ledge path checks and retain safe rolls, spacing, jumps and rare parries between risky exchanges.
- After 12 seconds with no living human ally, bots shorten regrouping and increase their existing risk preferences. This is situational pressure, with no health drain, damage multiplier, invulnerability or forced death timer.
- Checks: `tests/bot-behavior.cjs` includes physical punished trades/rolls, combo greed, walls, last-stand pressure and partner/bolt overrides. Run all profiles in `tests/bot-duel.cjs` and the existing bot/browser and solo suites. Duel reporting includes all resolution times and damage taken. `tests/bot.cjs` checks contribution and completion within three minutes rather than requiring 29/30 solo wins. See `docs/bot-risk-v7.13.1.md`. VERSION / LOAD_STAMP: v7.13.1 / 7.13.1.

## Bot combat rhythm and jump defence (v7.13.0)
- Plans own movement until their data-driven `commitAt`; a generic safe window must not erase baiting/flanking. Profiles add `burst`, `reset`, `think`, `evade` and `jumpDodge`. Count actual swings, decide each combo extension once, and take short bounded retreats. Ripostes, broken/staggered opponents, substantial recoveries and safe finishing windows override ordinary restraint; the arena-wide tracking and standoff fallback remain.
- `CONFIG.bot.parryChanceScale` is 0.1 (effective profile probabilities: 5.5%, 3%, 8%). Spacing is tried when a clear walking path can escape the hitbox, with a roll fallback if tracked or boxed in. Never walk back into an active swing.
- `bot.jumpLead` derives jump eligibility from the hitbox top/ground flag, player jump velocity/gravity, active duration and upcoming hits/follow-ups. Defensive jumps use real Player inputs/physics, require ground/stamina/landing room, and are vetoed by other threats/projectiles. No enemy ids or artificial invulnerability.
- `tests/bot-behavior.cjs` covers rhythm, re-engagement, per-swing choices, 6,000 eligible parry opportunities, real jump clearance, unsafe jump vetoes, walking escapes and random jump/roll mixes. Also run all profiles in `tests/bot-duel.cjs`, the bot integration/browser checks and full solo suite before release. See `docs/bot-rhythm-v7.13.0.md`. VERSION / LOAD_STAMP: v7.13.0 / 7.13.0.

## Friendly bots (v7.11.0)
- The lobby leader adds up to `ArenaNet.config.maxBots` (3) bots (`control` actions `addBot` / `removeBot`, leader-only). A bot is an ordinary `Player` on the server (`server/simulation.js`), its presses coming from `BotHands` (`js/bot.js`) through `Player.ctl` (the global `input` for people); it uses every player move: rolls, parries and ripostes, light combos, charged and leaping heavies, flasks and executions. Its blows go through `resolveCombat`, its damage is credited to the leaderboard, and bolts are flown against it on the server. Clients see it as a remote player (`bot: true`, a chase-camera `view` for spectators). A standing bot keeps a boss attempt alive (no team wipe); it respawns in levels and catches up with the party.
- The brain reads only attack data (wind-up timing, holds, hit chains, reach from boxes/rings/lunges/dashes/leaps, `noParry`/`rollOnly`, reactions, cooldowns): never special-case an enemy. Tuning in `CONFIG.bot`; personalities in `BOT_PROFILES` (`js/data/bots.js`, validated at load). Checks: `node tests/bot.cjs` (controls, frames, wipe rules, 29/30 Giant Skeleton duels), `node tests/bot-duel.cjs all 6` (every boss), `tests/bot-browser.cjs`. ## Architectural Rules
Story boss additions live in `js/data/story-boss-moves.js`, loaded after `data/elden-bosses.js`: one cloned move for Giant Skeleton (Godfrey), two for Pillager Captain (Godrick/Crucible Knight), and two for Bell Warden (Radagon; Skyfall Toll's area shockwave was removed for balance). Their HP in `enemies.js` is doubled to 1920 / 1800 / 2600. The clones keep source timings, poses and movement, with story damage tuning and no foreign follow-up references; `origin: { enemy, attack }` records each source. Level 2's throne pair are regular enemies. Aldric and the Elden Ring source bosses are unchanged. Tests: `run('Story boss moves')`.

1. **Content is Data:** All game entities (enemies, levels, items, attacks) must reside as plain data objects in `js/data/` or `js/levels/`[cite: 1]. Do not hardcode content into engine logic[cite: 1].
2. **ID Referencing:** All entities, objects, and assets must be referenced strictly by string `id`, never by array index[cite: 1].
3. **Fail-Fast Validation:** Validate data schemas and references on initialization[cite: 1]. Broken references must throw an explicit, readable error at load[cite: 1].
4. **Configuration Isolation:** Numeric balance, physics constants, and tuning parameters belong in `CONFIG` or data definitions, never scattered through procedural logic[cite: 1].
5. **Opt-In Mechanics:** New gameplay mechanics must remain data-driven and opt-in per entity/level so existing assets remain backward-compatible[cite: 1].
6. **Event-Driven Decoupling:** Combat and physics logic communicate outwards via `js/events.js` (e.g., `strike`, `dodge`, `parry`)[cite: 1]. Visuals, camera effects, HUD, and audio must listen to events rather than injecting into combat loops[cite: 1].
7. **Fixed Simulation Step:** Combat and physics simulate on a fixed 1/60s step, with rendering handling visual interpolation[cite: 1].
8. **Render Separation:** `js/visuals.js` and post-processing only handle drawing and cannot alter game state, collisions, or layout coordinates[cite: 1].
## Attack Animation (four phases, v4.2)
- An attack is wind-up -> active (the only phase with a hitbox) -> follow-through (`follow` per hit) -> recovery, on one clock (`attackTimeline`, `js/character.js`). Draw and hitbox read the same timeline, so they cannot disagree.
- Opt in per attack with `pose: '<id>'` (`ATTACK_POSES`, `js/data/attack-poses.js`): additive key poses (windup, strike, follow) per hit, eased per phase and lagged per joint (legs -> hips -> spine -> arm -> blade). Optional `poseScale` (bosses), `charge` (player heavy), `markers` (`sound`, `shake`, `glint`; `parry: true` glints as the parry window opens). Engine: `js/attack-anim.js` (also validates these fields).
- Enemies: `tracking: { rate, commit }` turns only for `commit` of each wind-up, then locks. A hit's `hold: { at, time, chance }` is a delayed attack, frozen still. No `pose` keeps the legacy `ANIMS` path (the training dummies).
- Player input: one Souls-style buffer slot (`Player.bufferInputs`, `CONFIG.player.bufferWindow`); combos chain through `next` on an attack.
- Feel, all visual: `js/impact.js` (strike shake, hit shudder, enemy trails), cloth and turn lag in `js/animator.js` / `ANIM_SETTINGS`, `Rig.weightLean`. Dev: `js/debug-combat.js` (F6 slow motion, F7 tracking colours).
- Changing a timing? Log old and new in `docs/combat-timings-v4.1.md`. Keep an enemy hit's `active` under the roll's i-frames (`CONFIG.player.rollIFrames`, 0.3 s) by a margin; move extra time into `follow` (a test checks the bosses).

## Executions (v5.2)
- **What:** a full stagger, guard or posture meter sends an enemy to its knee (`ES.BROKEN`, for the meter's `breakTime`; unchanged). The old bonus (`posture.damageMul`, 1.6× damage on a kneeling boss) is **removed** (and no longer validated); the reward is the execution. Kneelers: stagger meter (Knight, Executioner, Empty Sentinel), guard meter (Shield Warden, Shover), posture (Giant Skeleton, Pillager Captain, Bell Warden, Aldric, every phase). Poise-only enemies (Hollow, Rogue, Lancer, Duelist, Bowmen, Gargoyle, Wisp) never kneel, so they cannot be executed.
- **Files:** engine `js/execution.js` (`execution`: `target`, `start`, `update`, `mark`, `cameraWeight`, `damageFor`, `breakNearest`; `executePose` and `executedPose` draw both bodies). Tuning: **all numbers in `CONFIG.execution`** (`js/config.js`): `range` (m between body edges), `cone` (rad either side of the enemy's facing), `facing`, `floor`, `angleWeight`, `snapTime`, `standoff`/`gap` (where the player ends up), `chest`/`thrustHeight` (the thrust tilts up into a tall boss's chest), `damage` (`lightMul` 5 for normal enemies: 18 × 5 = 90; `bossLightMul` 18 for bosses: 18 × 18 = 324, capped at `bossCap` ≤ 0.5 of a boss's current bar), `hitstop`, `grace`, `push`, `shake`, `camera`, `cuePulse`, `bursts`. The animation is the player attack `execute` (`js/data/player.js`: wind-up 0.46 / active 0.08 / follow 0.5 = the hold / recovery 0.5 = the pull-out) with key poses `executeThrust` (`js/data/attack-poses.js`). Validated at load (`js/validate.js`).
- **Flow:** executions cost no stamina and work while exhausted (checked before `refuseIfExhausted`). `Player.tryGroundAction` (and a buffered light in an attack's recovery) asks `execution.target` (kneeling, alive, same floor, no gate between, within `range`, in the front `cone`, player roughly facing it; the best of several by distance + angle). `start` puts the player in `PS.EXECUTE` and the enemy in `ES.EXECUTED` (no AI, no hitbox, in `ENEMY_GROUPS.invulnerable`). The wind-up slides the player into place by velocity, with `integrateBody` edge sense on (walls and ledges stop it, never through or over). As the active phase opens: damage, hitstop, event `execution`. Recovery start: `executionPull`; a normal enemy dies (or, if it survives, is pushed back into `ES.STAGGER` with empty meters) here. End: `executionEnd`, then a boss is resolved.
- **Boss thresholds:** a blow that would empty a bar leaves 1 hp until the animation ends; then `Enemy.outlast()` runs as for any killing blow: Aldric's `field` bar → retreat (`bossRetreat`), `throne` → transition (`bossPhase`), `knell` / any last bar → death (`enemyDeath`, the ending). Always after `executionEnd`, with the player back in `PS.IDLE`.
- **Safety:** `Player.invulnerable()` is true for the whole of `PS.EXECUTE` and `execGrace` (`grace` s) after, so enemy blows, bolts and shockwaves pass (no `dodge` event: that is only for rolls). Presses during it are swallowed (`SWALLOWED`). Traps do not trigger under an executing player. If the victim leaves `ES.EXECUTED` by another cause (dies, falls), the player skips to the pull-out and ends cleanly. The player–victim pair is not separated (`separateBodies`), so the blade can pass through.
- **Feel (events, visual and audio only):** `js/boot.js` (blood burst at the chest, embers out of the back, shake), `js/audio.js` (flesh + riposte boom + break crack; the `hitFlesh` marker on the pull-out), the camera leans in (`Game.updateCamera`, `CONFIG.execution.camera`). Cue: the HUD's `#execCue` ("Execute" + the light key) and a red pulse on the enemy (`Enemy.execReady`, set each step by `execution.mark`).
- **Tutorial:** step `execute` (after `dodge`) with `executionDummy` (`TRAINING_DEFS`, a dummy with a quick `stagger` meter; training dummies with `stagger` now fill it and kneel, `level.training.execution`). Done on `executionEnd`.
- **Rules that must not be broken:** the player is untouchable from the first frame of an execution to the last and for `grace` after; a boss's death, phase change or retreat never starts mid-execution; boss damage never above half a bar (`bossCap`, validated); no numbers outside `CONFIG.execution`; executions only on `ES.BROKEN` enemies.
- **Boss tuning (v5.2):** every boss bar was doubled (Giant 960, Captain 900, Bell Warden 1300, Aldric field 1600 / throne 1800 / knell 2000) and boss `posture.decay` halved, for long, tough duels (a bonfire always comes before a boss).
- **Dev (`#dev`):** **F4** fills the nearest enemy's meter (it kneels at once); console `execution.breakNearest()`. Tests: `run('Execution')`.
- **Known gaps:** on very bulky models (Aldric's armour) the blade tip is hidden inside the body; the ember burst at the back sells the exit. The executed body may overlap a wall it kneels against (drawn only). The tutorial dummy only needs heavies; its light hits fill it slower.

The Graphics option cycles **Auto** (the detected preset, shown "Auto (Ultra)"), Low, High, Ultra; `autoQuality.effective()` is what is drawn. Tuning for everything Ultra: `CONFIG.VISUALS.ultra`.

## Conservative Auto graphics (v7.0.1)
- `CONFIG.VISUALS.autoQuality`: High requires <= 8 ms per reference pass, Ultra <= 7 ms (v7.0.4 desktop calibration), using the slowest of three synchronized rounds. Candidate costs scale with actual viewport pixels and each preset's pixel-ratio cap relative to 1280x720; small windows cannot relax the limits.
- Older/generic integrated GPUs, software renderers, small touch devices, and reported CPU/RAM below 6 logical threads / 8 GB start on Low and skip the benchmark. Modern integrated families can earn High. Unknown renderers cap at High; recognized strong GPUs can earn Ultra (at least 8 reported threads when available). Missing hardware hints do not imply weak hardware. Failed timings choose Low.
- Saved Auto choices are reassessed per page load; explicit Low/High/Ultra selections are preserved. Pure policy: `autoQuality.recommend(sample)`. Tests: `run('Auto quality')`. Release notes: `docs/auto-quality-v7.0.1.md`.

## Auto refresh and release caching (v7.0.5)
- `LOAD_STAMP` in `combat-arena-3d.html` must match `VERSION` without the leading v. `tests/autoquality.cjs` and the browser suite check this so new tuning cannot reuse an older release cache key.
- `autoQuality.recheck()` discards the in-page detection and runs it again. Options → Check graphics again explicitly selects and saves Auto, reruns detection and applies it. Returning to Auto in the Graphics cycle also rechecks. Existing manual choices otherwise remain untouched.
- `autoQuality.result()` exposes the current detection even for an existing Auto setting, including `version`, `checkedAt` and whether a benchmark was attempted. Timings/results are never stored in localStorage.

## Measured Auto graphics (v7.1; supersedes the v7.0.1/v7.0.4 selection policy)
- `js/quality-benchmark.js` renders a detached scene described in `js/data/auto-quality.js`, using real player/enemy/boss rigs, materials, point lights, MSAA, bloom, cached metal environment, and Ultra moon shadows plus representative reduced depth/normal and screen-light work. It never starts a level or touches combat/story/save state.
- Each candidate is rendered at the current viewport and its own pixel-ratio cap. Warm compilation/uploads are excluded; the median of five synchronized four-frame rounds is compared directly against `CONFIG.VISUALS.autoQuality.frameMs` (14 ms High/Ultra). No shader/pixel extrapolation. All renderer state and temporary resources must be restored/disposed even on failure.
- Known older integrated/software/touch renderers remain Low; modern integrated families cap at High. Dedicated and masked/unknown adapters can earn Ultra from the frame test. Browser CPU/RAM hints are diagnostic only, not hard gates. A slow or failed Ultra test tries High; both slow/failed tests select Low.
- Options → Check graphics again shows the detected GPU, frame costs and the exact decision reason. `autoQuality.result()` keeps frame samples, actual buffer sizes and errors in memory. Tests: `run('Auto quality')` and `node tests/autoquality.cjs`; cache stamp must match VERSION.
