# Project Guidelines

Current version: **v5.4 — Godrick the Grafted** (`VERSION` in `js/config.js`). The game is complete: Story mode (Tutorial, Levels 1–5, the ending), plus Levels, Enemies (duels) and Elden Ring Bosses, with its lore told by an NPC, inscriptions and scenes. v5.2 added executions; v5.3 added the Elden Ring Bosses mode and its first boss, Margit; v5.4 adds the second, Godrick the Grafted.

**`LORE.md` is the source of truth for the story.** Every in-game story text (dialogues, inscriptions, chapter lines, boss names, level descriptions, ending cards) must agree with it. Change the story in LORE.md first, then in the game, and keep LORE.md updated.

## Tech Stack
- **Engine / Core:** Vanilla JavaScript (ES6+), Three.js r160[cite: 1].
- **Structure:** Classic scripts loaded via `<script>` tags sharing a global execution context, loaded strictly in the order listed in `GAME_FILES` inside `combat-arena-3d.html`[cite: 1].
- **Dependencies & Tooling:** Zero build steps, bundlers, or third-party npm runtime dependencies[cite: 1].

## Run & Test Commands
- **Launch:** Open `combat-arena-3d.html` directly in any modern browser[cite: 1].
- **Dev Mode / Test Grounds:** Append `#dev` to the address (`combat-arena-3d.html#dev`) to enable test levels and suites[cite: 1].
- **Test Suite:** Execute in the browser developer console:
  - Run all tests: `await __arena.tests.run()`[cite: 1]
  - Run filtered tests: `await __arena.tests.run('<filter_keyword>')` (e.g., `run('heights')`)[cite: 1]
  - Run tests before every commit when modifying core combat, terrain, or movement logic[cite: 1].

## Architectural Rules
1. **Content is Data:** All game entities (enemies, levels, items, attacks) must reside as plain data objects in `js/data/` or `js/levels/`[cite: 1]. Do not hardcode content into engine logic[cite: 1].
2. **ID Referencing:** All entities, objects, and assets must be referenced strictly by string `id`, never by array index[cite: 1].
3. **Fail-Fast Validation:** Validate data schemas and references on initialization[cite: 1]. Broken references must throw an explicit, readable error at load[cite: 1].
4. **Configuration Isolation:** Numeric balance, physics constants, and tuning parameters belong in `CONFIG` or data definitions, never scattered through procedural logic[cite: 1].
5. **Opt-In Mechanics:** New gameplay mechanics must remain data-driven and opt-in per entity/level so existing assets remain backward-compatible[cite: 1].
6. **Event-Driven Decoupling:** Combat and physics logic communicate outwards via `js/events.js` (e.g., `strike`, `dodge`, `parry`)[cite: 1]. Visuals, camera effects, HUD, and audio must listen to events rather than injecting into combat loops[cite: 1].
7. **Fixed Simulation Step:** Combat and physics simulate on a fixed 1/60s step, with rendering handling visual interpolation[cite: 1].
8. **Render Separation:** `js/visuals.js` and post-processing only handle drawing and cannot alter game state, collisions, or layout coordinates[cite: 1].
## Attack Animation (four phases, v4.2)
- An attack is wind-up -> active (the only phase with a hitbox) -> follow-through (`follow` per hit) -> recovery, on one clock (`attackTimeline`, `js/character.js`). Draw and hitbox read the same timeline, so they cannot disagree.
- Opt in per attack with `pose: '<id>'` (`ATTACK_POSES`, `js/data/attack-poses.js`): additive key poses (windup, strike, follow) per hit, eased per phase and lagged per joint (legs -> hips -> spine -> arm -> blade). Optional `poseScale` (bosses), `charge` (player heavy), `markers` (`sound`, `shake`, `glint`; `parry: true` glints as the parry window opens). Engine: `js/attack-anim.js` (also validates these fields).
- Enemies: `tracking: { rate, commit }` turns only for `commit` of each wind-up, then locks. A hit's `hold: { at, time, chance }` is a delayed attack, frozen still. No `pose` keeps the legacy `ANIMS` path (the training dummies).
- Player input: one Souls-style buffer slot (`Player.bufferInputs`, `CONFIG.player.bufferWindow`); combos chain through `next` on an attack.
- Feel, all visual: `js/impact.js` (strike shake, hit shudder, enemy trails), cloth and turn lag in `js/animator.js` / `ANIM_SETTINGS`, `Rig.weightLean`. Dev: `js/debug-combat.js` (F6 slow motion, F7 tracking colours).
- Changing a timing? Log old and new in `docs/combat-timings-v4.1.md`. Keep an enemy hit's `active` under the roll's i-frames (`CONFIG.player.rollIFrames`, 0.3 s) by a margin; move extra time into `follow` (a test checks the bosses).
## AI, checkpoints and stamina (v4.2.4)
- Enemy states add `SEARCH` (lost sight: walks to `lastSeen`, looks about, goes home; `CONFIG.ai.search`). Unaware states in `ENEMY_GROUPS.narrowSight` see only in `CONFIG.vision.cone`. Alerts wake every enemy with the same `zone` (zone members, and dispersed entries with `zone`). Optional per-enemy `kite` (0..1): chance it keeps its distance after an attack or flinch instead of stepping in.
- Bonfires are checkpoints: `Game.cleared` holds the placement keys (`Game.placementKey`) of enemies dead at the last rest; they never respawn until a level restart. **v5.1:** on a death every other kill comes back (`Game.respawnEnemies`), including the fighters of zones already won (their gates stay open); only beaten bosses (a `boss` placement, `phases` or `posture`) stay beaten without a rest. A zone member with `arena: true` sees the player (and answers alerts) only inside its zone's trigger (the Bell Warden, so the bell bonfire is safe).
- Player exhaustion: `Player.spend` to 0 sets `exhausted`; `canAct()` gates every stamina action (`CONFIG.player.exhaustDelay`, `exhaustRecover`); refused presses emit `staminaDenied`.
- A room may set `railHeight` (lower rails the player can jump). Levels and duels start behind a loading screen (`Game.showLoading`, `CONFIG.loading`); there is no start notice screen.
## Character Models (procedural, no asset files)
- An enemy or the player opts in with `model: '<id>'` (`js/data/enemies.js`, `js/data/player.js`); without it the old box body is used. Definitions live in `js/data/models.js` (format, Hollow Soldier, player), `models-enemies.js` and `models-bosses.js`; a model can `extends` another. Parts and weapons come from `KIT_PARTS` / `KIT_WEAPONS` in `js/bodykit.js`; textures from `js/data/textures.js` via `TEXLIB` (`js/textures.js`).
- The skeleton is fixed (names in `js/bodykit.js`) so key poses and the legacy attack animations keep driving it. Secondary motion (breathing, flinch, death buckle, cloth springs, weapon glint, death dissolve) is `js/animator.js` + `js/data/animations.js`: visual only.
- One skinned mesh per material, geometry shared per model, materials cloned per body. Budgets: ~1,500 triangles normal enemy, ~3,000 player, ~6,000 boss (warned at load). Textures are generated once and cached; `KIT.prewarm()` bakes them while the menus are up.
- A placement can add `variant: 'elite'` (`MODEL_VARIANTS` in `models.js`): darker, spiked and horned, with an aura. Visual only.
- Dev viewers (`#dev`): F8 texture lab, F9 model lab (`MODELLAB.open('<model id>')`, `MODELLAB.pose('<mode>', seconds)`).
## Boss phases, Level 5 and the finale (v4.3)
- **Boss phases:** an enemy def with `phases: { <id>: { hp, name?, attacks: [ids], transition?, ignite?, ...any def field } }`. A placement picks them with `boss: { phases: [...] }` (else the def's `defaultPhases`). `Enemy.enterPhase` builds `this.def` as the base def with the phase's fields over it, so AI, HUD and timings read the phase. When a bar empties, `Enemy.outlast` starts the next phase (`ES.PHASE`: kneels, invulnerable, the bar refills over `transition` s) or, on the last one with `boss.retreat`, a scripted leap away (`ES.RETREAT` then `ES.GONE`, not alive, no death event). `ENEMY_GROUPS.invulnerable` lets blows pass through. Events: `bossPhase`, `bossRetreat`, `bossGone`, `bossLeap`.
- **New attack fields (per hit):** `box` (its own hitbox; `ring: { from, to, width, time }` is an expanding ring round the owner, tested in `Hitbox.overlaps`), `impact`, and `leap: { from, max, short }` (jumps along its locked aim at `from` of the wind-up, landing as the strike opens; no fall damage). All validated in `js/validate.js`.
- **Level fields:** `ending: true` (no LEVEL COMPLETE banner; `js/finale.js` runs the ending), bonfire `litBy: '<zone id>'` (cold until that zone is won; `Game.bonfireLit`), `sealed` gate `fog: '<zone id>'` (open until the player is inside with the fight on), `spectators` (out-of-reach sightings), `hints` (corpses before ambushes), `finaleRoom` (throne dressing), `devJumps`. Placements may set their own `notice`, `leash`, `homeLeash`; a `boss` placement never sleeps in culled levels. Dispersed behaviour `perch` (crouched on a ledge, leaps when you pass; grit falls and stone grinds first).
- **`js/finale.js`:** Level 5's script, all drawn or heard except the fog gate: sightings, corpses, the throne room and its transition timeline (`CONFIG.finale.timeline`), the burning look of an `ignite` phase, the boss pulse, perch grit, the ending cards, credits, the way back to the title, and the completion flag (`localStorage` `combatArena.complete`, a ✦ on the Levels menu). Dev (`#dev`): Level 5 jumps in Test Grounds, **F10** empties the current boss bar; console `__arena.finale`.
- **Level 5** (`js/levels/final-castle.js`): the field fight (Aldric's `field` bar ends in a retreat), Section A (outer ward, bridge Sentinel), Section B (great hall, ramparts), Section C (ash bridge, the processional gauntlet), the throne (`throne` then `knell`). New enemies: Gargoyle, Empty Sentinel, Toll Wisp; boss Aldric (`js/data/enemies.js`, models in `models-bosses.js` / `models-enemies.js`). Level 4 carries on into it (`next`).
- **Rules:** a transition must never deal damage; boss strikes keep `active` ≤ 0.22 s (tests check Aldric too); content stays in data, the finale only reads it.
- **Known gaps:** the throne room's falling pillars, glass and fire are drawn only (no collision). Tolling Chain's four cuts are all parryable (parry is per attack, not per hit). The Ash Wave is a projectile and can be blocked at block rates. Aldric's name on the bar changes as the transition starts, not when the bar refills.
- **v4.3.1 additions:** level flags `wakeZones` (while the player stands in a zone on its floor, its members and dispersed enemies with that `zone` stay awake and on them; a percher pounces) and `clearGates` (no lintel over gate doorways, open portcullises rise out of sight). Placement `wide: true` (sees all round when unaware); far-sighted placements are not culled within their notice. Projectile `look: 'slash'` (a flying crescent). `Game.camFocus` turns the camera to a scripted moment (Aldric's retreat). Ground shockwaves (Aldric's stomps and rings) top out at 0.6 m so a jump clears them. Gargoyles use their own claw poses (`clawRake`, `clawPounce`). Always give a placement `y` where floors overlap (a spawn without it stands on the top-most floor).
## Story mode and saving (v5.0)
- **Files:** content in `js/data/story.js` (`STORY`: `tutorial`, `chapters: [{ level, title, line, loadout? }]`, `progress` defaults), engine in `js/story.js` (`story`), tuning in `CONFIG.story` (`saveKey`, `saveVersion`, `titleTime`). Validated at load (`js/validate.js`): every chapter names a level in `LEVELS`, once.
- **Flow:** main menu: Story (no save) or Continue + New Game (confirm, `storyConfirm`), then `storyTutorial` (Yes / No). `Game.story` is on for the session; `showMenu('main')` turns it off. `Game.startLevel` shows the chapter `title` / `line` on the loading screen (`titleTime`) and saves. The next level is `Game.nextLevelId()`: the next chapter in Story mode, the level's own `next` otherwise. The tutorial's end (or pause → Skip tutorial) calls `story.afterTutorial()`. The finale emits `endingDone` when the player leaves the credits: Story marks the save complete and shows `storyDone`. R (restart) does nothing in Story mode.
- **Saving:** `localStorage[CONFIG.story.saveKey]`, written on `rest` (not in the tutorial), on every level start, by pause → Quit to main menu, and (v5.1) whenever a gate opens (a zone won, a shortcut) and when the page is hidden or closed. Only Story mode saves: the Levels menu never does. The save's optional `zones` lists won zones (Continue opens their gates; their unconfirmed fighters stand again). Every access is in try/catch (private windows play unsaved; `story.storageOk`).
- **Save format** (v1): `{ v, level, bonfire|null, spawn|null, cleared: [placement keys], shortcuts: [gate ids], traps: [trap ids], seen: [Level 5 sighting ids], bosses: [def ids], progress: { inventory: { <item>: { max } }, currency, equipment, upgrades }, completed, savedAt }`. `cleared` holds `Game.cleared` plus every actor of a won zone. A save with another `v`, an unknown level or bonfire, or a wrong field type is `broken`: the menu offers a new story. Changing the format: bump `saveVersion` (old saves are then refused) or migrate in `check()`.
- **Continue** (`story.resume`): starts the level, sets `cleared`, opens shortcuts, springs traps, marks zones whose members are all cleared as won (gate open, no event), `respawnEnemies()`, `finale.skipSightings`, then spawns at `spawn`.
- **Carry-over:** `story.applyProgress` runs in `Game.spawnPlayer`: each saved item capacity (clamped by the chapter's `loadout`), full. `captureProgress` reads the live player on every save. Health and flasks refill at every level start. Future currency / upgrades / equipment: add defaults to `STORY.progress` and read them in those two functions; unknown fields are kept.
- **Adding a level to Story:** make the level as usual, then add a chapter where it falls in `STORY.chapters`. Its `next` only matters for the Levels menu.
- **Dev (`#dev`):** main menu "Story: jump to a level" / "Story: clear the save"; console `__arena.story`. Tests: `run('Story')`.
- **Rules:** Story mode never changes a level; levels read nothing from it. Every storage access stays wrapped. Never write a save while `restoring`.
- **Known gaps:** kills after the last rest are not saved (Souls-like: they come back on Continue), but a won zone stays won. The Level 5 boss fights are not saved mid-fight. Carry-over today is only the flask count (4, fixed), so no level is affected; when upgrades arrive, use a chapter `loadout` clamp if one breaks a level's balance (the tutorial and Level 1 are the most sensitive).
## Lore, the NPC and subtitles (v5.1)
- **Files:** content in `js/data/lore.js` (`LORE`: `npc` (name, model `ysolde`), `ending` (the ending cards, read by `js/finale.js`), `levels[<level id>]`: `npcs` (a list: Level 5 has two; `after: '<zone id>'` shows her only once that zone is won, `bonfire` names her bonfire for dev jumps), `inscriptions`, `scenes`; `LORE_SCENES` lists the scene kinds), engine in `js/lore.js` (`lore`: `reset` / `update` from `Game`, a render hook, `prompt()` for the HUD, `jumpTo(id)`), tuning in `CONFIG.lore`. Validated at load (`js/validate.js`). The NPC's model is `MODEL_DEFS.ysolde` (`js/data/models.js`).
- **Seamless subtitles:** the Talk action (`ACTIONS.talk`: T / D-pad right) near the NPC (`talkRange`) or an inscription (`readRange`) plays every line as subtitles (`hud.subtitle`, `#subtitle` in the page), each held `lineBase + perChar × length` (clamped), with `lineGap` between. **No skipping:** a press during the dialogue does nothing and the prompt hides. It fades at once if the player is farther than `leaveRange`, on another floor, dead, or any enemy within `threatRange` is `fightingPlayer()`; Talk again starts from the first line. After the whole dialogue (`heard`), coming back plays the one `idle` line; Talk replays everything. No pause, no camera lock, no input taken.
- **NPC placement:** always by a bonfire, outside every zone trigger (a test checks), never in the path. She is a `Rig` only (not in `Game.enemies`): nothing can target, hit or kill her. She turns to face the player within `faceRange` and gestures while speaking. `pose: 'sit'` adds a crate under her. `solid: [x0, x1, z0, z1]` keeps the player out of a rect (her cell in Level 1, the alcove `cell-8` of `js/levels/long-hall.js`), `bars` draws the cell bars.
- **Scenes and inscriptions:** drawn only (`js/lore.js` builders per kind), shown within `sceneRange`. Positions stand on the floor at `y` (0 if left out; always give `y` on an upper floor, or where a roof lies overhead).
- **Adding a dialogue or inscription:** write it in LORE.md, then add it under its level in `js/data/lore.js` (`{ id, x, y?, z, yaw, mount: 'wall'|'floor'|'none', label, lines }`). A new scene kind: add its builder to `SCENE` in `js/lore.js` and its name to `LORE_SCENES`.
- **Rules that must not be broken:** no items, inventory or journal for lore; lore never blocks progress and never pauses the game; the NPC is never attackable and never dies; ids `varn` (the boss) and phase ids `field` / `throne` / `knell` stay (saves and data refer to them); only display names follow LORE.md.
- **Dev (`#dev`):** Test Grounds lists "Lore: Ysolde in <level>" jumps; console `__arena.lore`, `__arena.LORE`. Tests: `run('Lore')`.
- **Known gaps:** whether a dialogue was heard is not saved (it is per level visit). The cell bars of Level 1 are the only lore collision. Scenes do not collide. In low rooms (the tavern) the camera presses close, so the seated NPC is best seen up close.
## Executions (v5.2)
- **What:** a full stagger, guard or posture meter sends an enemy to its knee (`ES.BROKEN`, for the meter's `breakTime`; unchanged). The old bonus (`posture.damageMul`, 1.6× damage on a kneeling boss) is **removed** (and no longer validated); the reward is the execution. Kneelers: stagger meter (Knight, Executioner, Empty Sentinel), guard meter (Shield Warden, Shover), posture (Giant Skeleton, Pillager Captain, Bell Warden, Aldric, every phase). Poise-only enemies (Hollow, Rogue, Lancer, Duelist, Bowmen, Gargoyle, Wisp) never kneel, so they cannot be executed.
- **Files:** engine `js/execution.js` (`execution`: `target`, `start`, `update`, `mark`, `cameraWeight`, `damageFor`, `breakNearest`; `executePose` and `executedPose` draw both bodies). Tuning: **all numbers in `CONFIG.execution`** (`js/config.js`): `range` (m between body edges), `cone` (rad either side of the enemy's facing), `facing`, `floor`, `angleWeight`, `snapTime`, `standoff`/`gap` (where the player ends up), `chest`/`thrustHeight` (the thrust tilts up into a tall boss's chest), `damage` (`lightMul` 5 for normal enemies: 18 × 5 = 90; `bossLightMul` 18 for bosses: 18 × 18 = 324, capped at `bossCap` ≤ 0.5 of a boss's current bar), `hitstop`, `grace`, `push`, `shake`, `camera`, `cuePulse`, `bursts`. The animation is the player attack `execute` (`js/data/player.js`: wind-up 0.46 / active 0.08 / follow 0.5 = the hold / recovery 0.5 = the pull-out) with key poses `executeThrust` (`js/data/attack-poses.js`). Validated at load (`js/validate.js`).
- **Flow:** executions cost no stamina and work while exhausted (checked before `refuseIfExhausted`). `Player.tryGroundAction` (and a buffered light in an attack's recovery) asks `execution.target` (kneeling, alive, same floor, no gate between, within `range`, in the front `cone`, player roughly facing it; the best of several by distance + angle). `start` puts the player in `PS.EXECUTE` and the enemy in `ES.EXECUTED` (no AI, no hitbox, in `ENEMY_GROUPS.invulnerable`). The wind-up slides the player into place by velocity, with `integrateBody` edge sense on (walls and ledges stop it, never through or over). As the active phase opens: damage, hitstop, event `execution`. Recovery start: `executionPull`; a normal enemy dies (or, if it survives, is pushed back into `ES.STAGGER` with empty meters) here. End: `executionEnd`, then a boss is resolved.
- **Boss thresholds:** a blow that would empty a bar leaves 1 hp until the animation ends; then `Enemy.outlast()` runs as for any killing blow: Aldric's `field` bar → retreat (`bossRetreat`), `throne` → transition (`bossPhase`), `knell` / any last bar → death (`enemyDeath`, the ending). Always after `executionEnd`, with the player back in `PS.IDLE`.
- **Safety:** `Player.invulnerable()` is true for the whole of `PS.EXECUTE` and `execGrace` (`grace` s) after, so enemy blows, bolts and shockwaves pass (no `dodge` event: that is only for rolls). Presses during it are swallowed (`SWALLOWED`). Traps do not trigger under an executing player. If the victim leaves `ES.EXECUTED` by another cause (dies, falls), the player skips to the pull-out and ends cleanly. The player–victim pair is not separated (`separateBodies`), so the blade can pass through.
- **Feel (events, visual and audio only):** `js/boot.js` (blood burst at the chest, embers out of the back, shake), `js/audio.js` (flesh + riposte boom + break crack; the `hitFlesh` marker on the pull-out), the camera leans in (`Game.updateCamera`, `CONFIG.execution.camera`). Cue: the HUD's `#execCue` ("Execute" + the light key) and a red pulse on the enemy (`Enemy.execReady`, set each step by `execution.mark`).
- **Tutorial:** step `execute` (after `dodge`) with `executionDummy` (`TRAINING_DEFS`, a dummy with a quick `stagger` meter; training dummies with `stagger` now fill it and kneel, `level.training.execution`). Done on `executionEnd`.
- **Rules that must not be broken:** the player is untouchable from the first frame of an execution to the last and for `grace` after; a boss's death, phase change or retreat never starts mid-execution; boss damage never above half a bar (`bossCap`, validated); no numbers outside `CONFIG.execution`; executions only on `ES.BROKEN` enemies.
- **Boss tuning (v5.2):** every boss bar was doubled (Giant 960, Captain 900, Bell Warden 1300, Aldric field 1600 / throne 1800 / knell 2000) and boss `posture.decay` halved, for long, tough duels (a bonfire always comes before a boss).
- **Dev (`#dev`):** **F4** fills the nearest enemy's meter (it kneels at once); console `execution.breakNearest()`. Tests: `run('Execution')`.
- **Known gaps:** on very bulky models (Aldric's armour) the blade tip is hidden inside the body; the ember burst at the back sells the exit. The executed body may overlap a wall it kneels against (drawn only). The tutorial dummy only needs heavies; its light hits fill it slower.
## Elden Ring Bosses and Margit (v5.3)
- **Mode:** main menu "Elden Ring Bosses" -> the boss select (`Game.screens().elden`, one button per boss: name, stars, title and description, then Back) -> `elden.start(id)` = `Game.startFight(enemy)` in the Enemies arena (`ARENA`, reused) with `Game.eldenBoss` set. Victory: the usual ENEMY FELLED banner (hint `CONFIG.elden.victoryHint`), then after `victoryTime` s the `eldenWon` screen offers Retry / Boss select (v5.4). Death: at `deathMenu` s (before the normal respawn) the `eldenDeath` screen offers Retry / Boss select. Pause -> Back to Menu returns to the boss select. Engine: `js/elden.js` (flow only); tuning `CONFIG.elden`. `startFight` / `startLevel` clear `eldenBoss`, so Enemies duels and levels behave as before.
- **Boss registry:** `js/data/elden-bosses.js`: `ELDEN_BOSS_DEFS` (the defs, added to `ENEMY_BY_ID` but not to `ENEMY_DEFS`, so they are not in the Enemies list) and `ELDEN_BOSSES` (`{ id, enemy, name, title, difficulty 1-5, description }`, validated). **Adding a boss:** write `js/data/bosses/<boss>.js` (its poses, `MODEL_DEFS` entry and def, as `margit.js`), add it to `GAME_FILES` before `data/elden-bosses.js`, put the def in `ELDEN_BOSS_DEFS` and add one entry to `ELDEN_BOSSES`. The menu needs no change.
- **Margit:** everything in `js/data/bosses/margit.js` (reference `docs/Margit/margit-stats.txt`). Model `margit` (hood, beard, cloak, `tail` part, `cane` weapon in `js/bodykit.js`). Balance: one 3200 HP bar; phase `omen`, then `golden` at 60 % on the same bar (opens with `hammerOpener`, cooldown [0.7, 1.5] from [1.1, 2.1], more approach); posture max 130, `parry` 65 (two parries break him); cane 22-46 damage, golden weapons 34-60, daggers 16-18 (player: 120 HP, light 18, heavy 38). - **New opt-in engine fields (`js/enemy.js`, validated in `js/validate.js`):** attack `when` (a reaction rolled per second, ignoring cooldown and facing: `behind`, `flank`, `healing`, `staggered`; `REACTIONS`, angles in `CONFIG.ai.reactions`; such attacks are left out of normal choice and reach), `followUps: [{ attack, chance, if? }]` (a branch as the last hit ends, `FOLLOW_IF`: any, far, near, flank, behind), a hit's `abort: { at, beyond, into }` (backing off mid wind-up turns it into another attack), a hit's `leap.back` (a leap away), `noParry` (blockable, never parried; `js/combat.js`), `spectral: 'dagger'|'hammer'|'sword'` (a golden weapon drawn in the weapon hand during wind-up and strike; `js/spectral.js`, drawing only), projectile `look: 'dagger'`. A phase with `at` (fraction of the bar, no `hp`) starts mid-bar keeping health and posture (`Enemy.checkPhaseAt`, event `bossPhase` with `seamless`), with an optional `opener`; an emptied bar never refills into such a phase.

- **Known gaps:** the boss select is the menu's button list (name + stars, the title and description below), not illustrated cards. Margit's golden weapons are drawn on the cane hand (no separate left-hand animation); parry is per attack, so the Staff-to-Hammer spin's cane hit is not parryable either. The "flank" dagger is quick but still has a 0.5 s wind-up so it can be read. This mode is outside the story: LORE.md does not cover it.
